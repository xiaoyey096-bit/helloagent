1.1 什么是智能体

定义与四要素 · 传统智能体演进 · LLM 新范式 · 三种分类维度

要点术语答案与解释
智能体的定义四要素

能通过传感器感知环境,并自主地通过执行器采取行动以达成特定目标的实体。

四个基本要素:

  • 环境 (Environment):智能体所处的外部世界(道路/金融市场等);
  • 传感器 (Sensors):感知能力的延伸(摄像头/雷达/API 数据流);
  • 执行器 (Actuators):改变环境的手段(机械臂等物理设备 / 调用服务等虚拟工具);
  • 自主性 (Autonomy):真正赋予「智能」的核心——能基于感知和内部状态独立决策,而非被动执行预设指令。
传统智能体演进阶梯反应式 → 模型 → 目标 → 效用 → 学习

一条「从简单到复杂、从被动反应到主动学习」的演进路线:

  • ① 反射智能体 (Simple Reflex):核心是「条件-动作」规则(自动恒温器)。只依赖当前感知,无记忆无预测,像数字化本能。
  • ② 基于模型的反射智能体 (Model-Based):有内部世界模型,追踪无法直接感知的方面,有初级「记忆」(隧道中的自动驾驶)。
  • ③ 基于目标的智能体 (Goal-Based):主动有预见地规划导向目标的行动(GPS 用 A* 算法规划路径)。
  • ④ 基于效用的智能体 (Utility-Based):为每个状态赋效用值,在多冲突目标间权衡,最大化期望效用(最短+最省油+避开拥堵)。
  • ⑤ 学习型智能体 (Learning Agent):含性能元件 + 学习元件,通过与环境互动自主学习修正策略;强化学习 (RL) 是其代表路径(AlphaGo Zero)。
LLM 驱动的新范式规划与推理 · 工具使用 · 动态修正

以 GPT 为代表的 LLM 改变了智能体的核心决策机制。传统智能体能力源于显式编程(确定、有边界);LLM 智能体靠海量数据预训练获得隐式世界模型与涌现能力(灵活、通用)。

以「智能旅行助手」为例,体现三点:

  • 规划与推理:把高层级目标分解为子任务(确认偏好→查询信息→制定行程→预订);
  • 工具使用:识别信息缺口,主动调用外部工具补全(调天气 API → 据雨天推荐室内活动);
  • 动态修正:把用户反馈(超预算)视为新约束,调整后续行动。

核心转变:从「编写代码」转向「引导一个通用的『大脑』去规划、行动、学习」。
分类维度①:内部决策架构反应式 / 模型式 / 目标 / 效用 + 学习元能力

依据内部决策架构的复杂程度(《人工智能:一种现代方法》):从反应式 → 模型式 → 基于目标 → 基于效用。学习能力是可赋予上述所有类型的「元能力」。
分类维度②:时间与反应性反应式 / 规划式 / 混合式

关注智能体是立即行动还是深思熟虑后规划。核心权衡:追求速度的反应性 vs 追求最优解的规划性。

  • 反应式 (Reactive):近乎即时响应、决策延迟低,感知→行动直接映射(安全气囊、高频交易)。优势是速度快开销低,代价是「短视」、易陷局部最优。
  • 规划式 (Deliberative):行动前用世界模型探索未来可能性,评估行动序列后果找最佳路径(棋手预想十几步)。优势是战略远见,代价是高昂的时间和计算成本。
  • 混合式 (Hybrid):结合两者。经典是分层设计(底层快速反应 + 高层审慎规划)。现代 LLM 智能体在「思考-行动-观察」循环中实现更灵活的混合。
分类维度③:知识表示符号主义 / 亚符号主义 / 神经符号主义

探究智能体用以决策的知识以何种形式存在——AI 领域半世纪辩论的核心:

  • 符号主义 (Symbolic AI):智能源于对符号的逻辑操作(规则库/知识图谱)。优势:透明可解释(金融医疗高风险领域重要);致命弱点「知识获取瓶颈」——依赖完备规则,现实世界新情况即失灵。
  • 亚符号主义 (Sub-symbolic / 连接主义):知识内隐分布在神经元网络中,从数据学统计模式(神经网络/深度学习)。优势:模式识别强、抗噪声;弱点是黑箱(无法解释为什么),纯逻辑推理差,会幻觉。
  • 神经符号主义 (Neuro-Symbolic):融合两者,既像神经网络学习、又像符号系统推理。类比卡尼曼《思考,快与慢》:
    • 系统 1:快速、直觉、并行 ≈ 亚符号(模式识别);
    • 系统 2:缓慢、有条理、基于逻辑 ≈ 符号(推理)。
    LLM 智能体是其绝佳范例:内核是神经网络,工作时却生成结构化中间步骤(思想/计划/API 调用这些符号)。

1.2 智能体的构成与运行原理

PEAS 任务环境 · 智能体循环 · Thought-Action-Observation 协议

要点术语答案与解释
PEAS 模型任务环境定义

用 PEAS 精确描述一个任务环境:

  • Performance 性能度量(目标达成好坏的标准);
  • Environment 环境(外部世界);
  • Actuators 执行器(改变环境的手段);
  • Sensors 传感器(感知环境的途径)。
任务环境的复杂特性部分可观察 / 随机性 / 多智能体 / 序贯动态

LLM 智能体所处数字环境的特性,直接影响设计:

  • 部分可观察:无法一次获取全部信息(航班 API 只返回部分数据) → 需记忆和探索能力;
  • 确定性 vs 随机性:行动结果是否可预测。票价搜索是随机性环境(两次调用结果不同) → 需处理不确定性;
  • 多智能体 (Multi-agent):环境中有其他行动者(其他用户、调价脚本) → 需快速响应;
  • 序贯 + 动态:序贯=当前动作影响未来;动态=环境自身会变化 → 「感知-思考-行动-观察」循环须快速灵活适应。
智能体循环Agent Loop · 感知-思考-行动-观察

智能体通过一个持续循环与环境交互,这是其自主行为的基础。三阶段:

  • ① 感知 (Perception):通过传感器接收环境输入 = 观察 (Observation)(用户指令或上一步行动的反馈)。
  • ② 思考 (Thought):核心决策阶段(LLM 驱动),细分两环节:
    • 规划 (Planning):基于观察和记忆,更新理解,制定/调整行动计划,可能分解子任务;
    • 工具选择 (Tool Selection):从工具库选最适合下一步的工具及参数。
  • ③ 行动 (Action):通过执行器执行(调用代码解释器/搜索 API),改变环境状态。

行动引起环境状态变化,产生新的观察反馈,被下一轮感知捕获 → 持续闭环。
交互协议Thought / Action / Observation

为让 LLM 有效驱动循环,需明确的交互协议。智能体输出是结构化文本,含两部分:

  • Thought (思考):内部决策「快照」,用自然语言阐述如何分析情境、回顾观察、自我反思、规划下一步。
  • Action (行动):基于思考决定的具体操作,通常为函数调用。
Thought: 用户想知道北京天气。我需要调用天气查询工具。
Action: get_weather("北京")

解析器 (Parser)捕捉 Action 指令调用对应函数;返回的原始数据(如 JSON)被封装成简洁自然语言 Observation,作为下一轮输入。

1.3 动手体验:5 分钟实现第一个智能体

智能旅行助手 · 提示工程 · 接入 LLM · 行动循环

要点术语答案与解释
提示工程指令模板 / system_prompt

驱动真实 LLM 的关键是提示工程:设计一个「指令模板」,告诉 LLM 它的角色、拥有的工具、如何格式化思考和行动,作为 system_prompt 传入。

模板要点:声明可用工具及签名;规定输出格式(Thought: ... Action: ...);Action 形式为「调用工具 function_name(arg="value")」或「结束任务 Finish[最终答案]」;每次只输出一对 Thought-Action。
工具(Tool)

工具是智能体与外部世界交互的「执行器」。本例两个工具:

  • get_weather(city):调 wttr.in API 返回 JSON,格式化为自然语言;
  • get_attraction(city, weather):调 Tavily Search API 搜索景点推荐。

所有工具函数放入字典 available_tools 供主循环调用。
接入 LLMOpenAI 兼容接口 · 三凭证

许多 LLM 服务商(OpenAI/Azure/Ollama/vLLM)都遵循兼容 OpenAI 的接口规范,带来标准化便利。实现通用客户端 OpenAICompatibleClient 可连任何兼容服务。

实例化需三信息:API_KEY、BASE_URL、MODEL_ID。其 generate(prompt, system_prompt) 方法构造 system+user 消息调用 chat completions 接口。
执行行动循环主循环四步 · 最大循环次数

主循环整合所有组件,驱动 LLM 决策。每轮:

  • ① 构建 prompt(拼接历史);
  • ② 调 LLM 思考,正则截断多余的 Thought-Action 对;
  • ③ 解析 Action:若 Finish[…] 则输出最终答案并 break;否则正则提取工具名和参数,从 available_tools 调用;
  • ④ 记录 Observation 追加到历史,进入下一轮。

设置最大循环次数(如 5)是必要的防护:防止智能体陷入无限循环/反复调用工具。

核心是「工具」+「提示工程」的结合——这正是主流框架(LangChain/LlamaIndex)的设计精髓。
智能体四项基本能力任务分解 / 工具调用 / 上下文理解 / 结果合成

旅行助手案例演示了基于 Thought-Action-Observation 范式的四项能力:任务分解、工具调用、上下文理解、结果合成。通过循环不断迭代,把模糊意图转化为具体可执行步骤并达成目标。

1.4 智能体应用的协作模式

开发者工具 · 自主协作者 · Workflow vs Agent

要点术语答案与解释
作为开发者工具GitHub Copilot · Claude Code · Trae · Cursor

智能体作为强大辅助工具增强而非取代开发者,自动化繁琐重复任务。代表产品:

  • GitHub Copilot:GitHub+OpenAI,深度集成 VS Code,以代码自动补全闻名,有 Copilot Chat 对话编程;
  • Claude Code:Anthropic,终端中用自然语言编码,理解完整代码库,支持 headless 无交互模式(CI/hooks/脚本);
  • Trae:新兴工具,智能代码生成与优化,轻量快速响应,适合频繁迭代/原型;
  • Cursor:AI 原生代码编辑器(非插件),设计之初就以 AI 交互为核心,强调让 AI 理解整个代码库上下文。
作为自主协作者目标-委托 · 三种架构范式

把高层级目标委托给智能体,它像项目成员独立规划、推理、执行、反思直到交付。关系从「命令-执行」演变为「目标-委托」。代表框架:BabyAGI、AutoGPT、CrewAI、AutoGen、MetaGPT、LangGraph。三种主流架构范式:

  • ① 单智能体自主循环(如 AgentGPT):通用智能体通过「思考-规划-执行-反思」闭环自我提示迭代;
  • ② 多智能体协作(最主流):模拟人类团队。细分:
    • 角色扮演式对话(CAMEL):为两个智能体设角色和沟通协议;
    • 组织化工作流(MetaGPT/CrewAI):模拟分工明确的虚拟团队(软件公司/咨询小组),各有职责和 SOP;AutoGen/AgentScope 提供更灵活的交互网络。
  • ③ 高级控制流架构(LangGraph):把执行过程建模为状态图 (State Graph),灵活可靠地实现循环、分支、回溯、人工介入。
Workflow vs Agent按部就班 vs 自主达成

一句话:Workflow 是让 AI 按部就班执行指令,Agent 是赋予 AI 自由度去自主达成目标。

  • Workflow(工作流):对任务预先定义、结构化编排的精确静态流程图。例:费用报销审批(金额分支判断),每步每条件都预先设定。
  • Agent(智能体):具备自主性、以目标为导向的系统,能理解环境、推理、制定计划、动态行动。LLM 扮演「大脑」。例:旅行助手——无写死的 if 天气=晴天 then 推荐颐和园 规则,而是基于实时信息动态推理决策(雨天则推荐室内场所)。

核心价值:Agent 基于实时信息动态推理和决策的能力。
