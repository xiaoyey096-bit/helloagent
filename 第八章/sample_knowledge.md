# 智能体记忆与检索:知识库样例文档

> 本文档作为第八章 RAG 演示的样例知识源,内容围绕"智能体记忆系统"与"检索增强生成"两大主题展开,
> 供 demo_rag.py 进行文档加载、分块、向量检索与智能问答演示。

## 一、记忆系统的四种类型

智能体的记忆系统通常划分为四种类型,各自承担不同职责:

- **工作记忆(Working Memory)**: 当前会话的临时信息,容量有限,用于存放正在处理的上下文。
  类似人脑的"短期记忆",会话结束后即可丢弃或被整合为长期记忆。
- **情景记忆(Episodic Memory)**: 记录具体事件与交互经历,带有时间戳与上下文。
  例如"用户昨天询问过向量数据库的配置方法"就是一条情景记忆。
- **语义记忆(Semantic Memory)**: 存储通用知识与事实,不依赖具体事件。
  例如"Qdrant 是一个开源向量数据库"属于语义记忆。
- **程序记忆(Procedural Memory)**: 关于"如何做"的技能与流程知识,如工具调用步骤、算法流程。

## 二、记忆的生命周期

一条记忆从产生到消亡,会经历以下阶段:

1. **编码(Encoding)**: 将外部信息转化为可存储的表示(如向量)。
2. **存储(Storage)**: 写入向量数据库(Qdrant)与图数据库(Neo4j)。
3. **检索(Retrieval)**: 通过语义相似度召回相关记忆。
4. **整合(Consolidation)**: 把重要的短期记忆提升为长期记忆。
5. **遗忘(Forgetting)**: 按重要性、时间或容量策略清除低价值记忆,避免信息过载。

遗忘策略常见有三种:基于重要性(importance_based)、基于时间(time_based)、基于容量(capacity_based)。
整合操作则把工作记忆中重要性超过阈值的内容转为情景记忆,模拟人脑"短期记忆固化为长期记忆"的过程。

## 三、检索增强生成(RAG)

RAG 是 Retrieval-Augmented Generation 的缩写,中文译为"检索增强生成"。
其核心思想是:在让大语言模型回答问题前,先从外部知识库中检索相关文档片段,
将其作为上下文注入提示词,从而让模型基于检索到的事实生成答案。

### RAG 的标准流程

1. **文档加载**: 读取 PDF、Word、Markdown、网页等多格式文档。
2. **分块(Chunking)**: 把长文档切成若干语义相对完整的小片段,便于精准检索。
   常见策略有固定长度分块、按段落分块、按标题层级分块。
3. **向量化(Embedding)**: 用嵌入模型把每个文本片段转为稠密向量。
4. **存储**: 将向量写入向量数据库(如 Qdrant),并保留原文与元数据。
5. **检索**: 把用户问题同样向量化,在向量库中做余弦相似度检索,取 Top-K 片段。
6. **生成**: 将检索到的片段拼进提示词,交给 LLM 生成最终回答。

### 高级检索技巧

- **多查询扩展(MQE, Multi-Query Expansion)**: 让 LLM 把原问题改写成多个语义相近的子问题,
  分别检索后合并结果,提升召回率。
- **假设文档嵌入(HyDE, Hypothetical Document Embedding)**: 先让 LLM 为问题生成一个"假想答案",
  用假想答案的向量去检索,更贴近答案所在的文档片段分布。
- **混合检索**: 结合向量检索(语义)与关键词检索(BM25),兼顾语义匹配与精确词命中。

## 四、向量数据库 Qdrant

Qdrant 是一款开源的向量数据库,核心特性包括:

- 基于 HNSW(Hierarchical Navigable Small World)索引实现近似最近邻搜索,检索速度快。
- 支持余弦相似度、欧氏距离、点积等多种度量方式。
- 支持负载过滤(filter),可在向量检索的同时按元数据条件筛选。
- 提供云服务(Qdrant Cloud)与本地部署两种形态。

在 hello-agents 框架中,记忆的向量存储与 RAG 的知识库向量都默认写入 Qdrant,
通过 collection(集合)与 namespace(命名空间)实现多租户隔离。

## 五、图数据库 Neo4j 在记忆系统中的角色

Neo4j 用于存储记忆的**关系结构**,而非向量本身。一条记忆被写入后,
框架会在 Neo4j 中创建对应的实体节点与关系边,例如:

- (记忆)-[:属于]->(记忆类型)
- (记忆)-[:关联]->(实体)
- (记忆)-[:发生於]->(时间)

这样在检索时,除了向量相似度召回,还能沿着图结构进行多跳推理,
回答"与某条记忆相关的其他记忆有哪些"这类关联型问题。

Neo4j Aura 是 Neo4j 的全托管云服务,其 home database(主数据库)名称等于用户名,
而非默认的 "neo4j",这是 Aura 与本地部署的一个重要差异。
